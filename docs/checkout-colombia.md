# Checkout Bakatá — Colombia

La plantilla page-bakata-checkout se resuelve por el ID de checkout configurado, excluyendo endpoints de pedido/pago. Preserva el contenido guardado de la página y los bloques Checkout de WooCommerce. Incluye un main, navegación al carrito y CSS acotado al checkout con tokens Bakatá. No introduce cálculo de totales, validación de pagos, datos personales adicionales ni modificación de pedidos. No se cambia la configuración de países ni medios de pago en producción.

WooCommerce 11.3.1 ya dispone de departamentos CO (CO-DC, CO-ANT, etc.), campo ciudad/municipio libre y código postal opcional. Se conservan estos mecanismos, el país configurado, moneda COP y validación nativa. No se implementa todavía un catálogo oficial DANE de municipios, documento de identidad, reglas tributarias, facturación electrónica ni exigencias comerciales no acordadas. Idioma de bloques nativos depende de WordPress, localización es_CO pendiente.

CI: después de todas las pruebas previas, fixture local restringido a localhost y WP_CLI configura país CO, zona Colombia, envío fijo ficticio de 12.000 COP y transferencia offline solo para comprobar presentación. No son tarifas comerciales ni se copian a Lightsail. Playwright bloquea solicitudes externas y POST de checkout, no pulsa finalizar pedido. Revisa entrada desde carrito, dirección sintética, departamento, código postal opcional, moneda, tarifa y total del servidor, resumen, CTA de pago, regreso al carrito, overflow y axe a 320/768/1440. WooCommerce puede crear borradores internos de checkout en entorno desechable; no se finalizan pedidos ni se procesa pago. No se usa información personal real. No se registran valores de los campos en los logs. Las capturas de CI son sintéticas.

Pendiente: primera ejecución; confirmar selectores nativos y comportamiento de envío, revisar capturas, validar errores de dirección/correo y métodos de pago, términos y privacidad publicados, impuestos, cobertura/municipios, pedido de prueba de extremo a extremo en sandbox explícito, reembolsos, idempotencia y webhooks. No se activa ninguna pasarela o envío comercial hasta elegir proveedores y configurar sandbox.
