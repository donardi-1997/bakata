# Bakatá Core — preparación de importaciones a borrador

DraftPlanner conecta SupplierProduct, UnitCosts, PricingPolicy y PricingPreview. Verifica moneda/exponente, costo del proveedor y frescura; recalcula la cotización, no admite un precio candidato arbitrario. La huella versión 1 incluye fuente (sin timestamp), costos, política y precio calculado. La observación nueva con mismos datos puede repetir una importación; una observación caducada nunca se acepta.

WooDraftImporter::create es una API PHP interna sin invocador registrado, no un endpoint REST, comando operativo, cron, acción administrativa o integración real. Requiere capacidad edit_products, moneda y decimales de la tienda compatibles, título normalizado y SKU estable. Utiliza CRUD WooCommerce. Crea exclusivamente un producto simple draft, hidden, sin precio regular/oferta/activo, inventario 0, outofstock, sin backorders. Guarda identidad, huella, observación, disponibilidad de proveedor y precio candidato en metadatos privados. El stock y precio candidatos no son valores de venta. No importa imágenes, descripciones, categorías, productos variables ni información fiscal.

Repetición secuencial idéntica: devuelve el ID si coincide identidad, huella, título e invariantes del borrador y el actor puede editarlo. Cualquier discrepancia, SKU ajeno, estado publicado, cambio editorial o cambio comercial se rechaza sin sobrescribir. No implementa reconciliación, actualizaciones ni bloqueo distribuido; el futuro orquestador debe serializar por SKU y proporcionar idempotencia persistente y auditoría. No se expone ningún invocador comercial antes de implementar estos controles. Si un hook externo altera el producto después de guardar, devuelve error para revisión manual; no promete rollback transaccional de WordPress. El flujo CI usa solo plugins del entorno desechable.

Prueba integrada: scripts/test-draft-import-ci.php, WP-CLI y BAKATA_CI_FIXTURES=1, exclusivamente localhost/127.0.0.1. Se comprueba permisos, cotización, frescura, coincidencia de costo, borrador oculto, ausencia de precio, stock cero, producto no comprable, replay secuencial, colisión con SKU de tercero, cambio editorial y rechazo de título no normalizado. Los registros sintéticos se crean después de QA de storefront y se destruyen con el volumen CI; no se ejecutan en Lightsail. No se cambian datos comerciales.

Pendiente: CI, proveedor/API/sandbox, mapeo de variantes, política comercial, permisos específicos y autorización operativa, concurrencia y transacciones, revisión editorial, administración, licencias de imágenes, trazabilidad y política de publicación. Ningún producto se publica ni se envía pedido a proveedor.
