# Bakatá Core — previsualización de fulfillment

Máquina de estados PHP pura por grupo de proveedor generado por OrderPreview. No se registra ningún invocador, webhook, HTTP, cron, UI o cola; no se modifica WooCommerce, ni se envían pedidos, ni se autoriza su envío. El estado inicial awaiting_confirmation es un estado de simulación, no confirma que se haya creado un pedido externo.

Estados: awaiting_confirmation -> accepted/rejected/cancelled; accepted -> preparing/shipped/cancelled; preparing -> shipped/cancelled; shipped -> in_transit/delivery_exception/delivered/returned; in_transit -> delivery_exception/delivered/returned; delivery_exception -> in_transit/delivered/returned; delivered -> returned. Rejected, cancelled y returned son terminales. No se acepta cancelación después del despacho ni regresión de entregado a tránsito. Se admite entrega directa desde shipped (no exigir eventos intermedios del transportador). El modelo es de un envío completo por grupo: múltiples paquetes, entregas parciales dentro de un grupo, cambios de guía y devoluciones parciales requieren ampliación antes de operar.

FulfillmentEvent exige referencia y huella del grupo, identificador de evento normalizado, estado, instante y, exclusivamente en shipped, código de transportador y guía opaca. No admite URLs ni texto libre como guía. No consulta ni valida la autenticidad de la guía. La guía puede ser información sensible y no debe incluirse en logs ni respuestas públicas. No se procesan firmas: entradas confiables o sintéticas únicamente. El futuro adaptador debe normalizar IDs, estados y tiempos según contrato.

Replay de historia completa y ordenada, máximo 1000 entradas. Rechaza grupo/huella incorrectos, futuro, transición inválida y cronología decreciente. En empate temporal se conserva el orden recibido (el adaptador futuro debe resolver secuencia fiable); deduplicación del mismo ID y huella normalizada incluso si llega al final; mismo ID con contenido diferente es conflicto. Huella usa instante Unix con microsegundos. Sin persistencia, bloqueo, protección de replay HTTP ni idempotencia transaccional. Un error invalida la previsualización completa; no produce resultado parcial. Ninguna aceptación o entrega simulada representa evidencia comercial.

Resumen exige una instantánea por cada grupo original con referencia y huella coincidentes, rechaza duplicados y omisiones. Estados agregados: awaiting_confirmation, in_progress, partial_delivery, all_delivered, attention_required, closed_without_delivery. Incidencias, rechazos, devoluciones y cancelaciones parciales requieren atención incluso si otros grupos llegaron. Si todos cerraron sin entrega vigente, closed_without_delivery (puede incluir devoluciones después de entrega). No se devuelve guía ni transportador en resumen. No se cambia estado, notas, pago, reembolso ni stock en WooCommerce. Las instantáneas son DTO internos; no se aceptarán como evidencia de terceros.

CI puro PHP 8.3: prueba el ciclo normal, incidencias, recuperación, retornos, cancelación, transiciones inválidas, duplicados, conflictos, fechas, grupos y resumen multiproveedor. Integra salida real de OrderPreview con mapeos sintéticos. Pendiente: persistencia atómica y control de versiones, autenticación de eventos y firmas, deduplicación duradera por proveedor y cuenta, normalización de estados/API, múltiples paquetes, autorización de despacho, reconciliación tras timeouts, reintentos limitados, trazabilidad y permisos antes de exponer vistas. Sin llamadas comerciales.
